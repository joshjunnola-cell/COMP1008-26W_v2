## Getting Started

Welcome to the VS Code Java world. Here is a guideline to help you get started to write Java code in Visual Studio Code.

## Folder Structure

The workspace contains two folders by default, where:

- `src`: the folder to maintain sources
- `lib`: the folder to maintain dependencies

Meanwhile, the compiled output files will be generated in the `bin` folder by default.

> If you want to customize the folder structure, open `.vscode/settings.json` and update the related settings there.

## Dependency Management

The `JAVA PROJECTS` view allows you to manage your dependencies. More details can be found [here](https://github.com/microsoft/vscode-java-dependency#manage-dependencies).

Group Reflection
Team Collaboration
This project was originally designed for three people, but due to unexpected circumstances, only the two of us, Josh and Kasib were available to complete all required tasks. Throughout the entire process, we worked closely together over Discord, which made communication smoother and allowed us to solve problems in real time. Even though we were short a member, we coordinated effectively and supported each other whenever one of us got stuck.

Task Distribution
Although the assignment was split into three roles (Student 1, Student 2, Student 3), we divided the work in a way that made sense for a two‑person team:

Josh
- Focused primarily on Student 1 tasks, which involved:
- Designing the Person and Course base classes
- Implementing inheritance and polymorphism
- Creating derived classes such as Student, Instructor, and the various Course types
- Ensuring the class hierarchy was clean, consistent, and aligned with OOP principles

Kasib
- Took on the responsibilities of Student 2 and Student 3, since these tasks were closely related:
- Implementing validation (IDs, names, emails, course codes, etc.)
- Adding exception handling
- Building the collection management features (searching, adding, listing objects)
- Creating the manager classes and search utilities

Shared Work
Once Josh completed the Student 1 tasks, he shifted to helping with the Student 2 and 3 tasks. We reviewed each other’s code, tested features together, and made sure our classes integrated smoothly. The collaboration was continuous and supportive, especially given the reduced team size.

Challenges We Faced
- Understanding the scope of base vs. derived classes:
At first, we weren’t sure how detailed the derived classes needed to be for Phase 1.
- Working with one fewer group member:
This added pressure and time constraints, especially since the assignment was time‑sensitive. We had to reorganize responsibilities quickly and efficiently.
- Coordinating GitHub workflow:
Thankfully, Kasib had strong experience working in group GitHub environments, which helped prevent merge conflicts and kept the repository organized.

What We Learned
- How to design and implement clean OOP hierarchies
- How to use inheritance, polymorphism, and abstraction effectively
- How to integrate validation, exception handling, and collections into a larger system
- The importance of clear communication, especially when team size changes unexpectedly
- How to adapt quickly when project conditions shift

How We Solved Problems
- We used Discord voice calls and screen sharing to debug issues together.
- When one of us got stuck, the other stepped in to help test or rethink the logic.
- We divided tasks based on strengths but remained flexible enough to assist each other.
- We frequently reviewed each other’s code to ensure consistency across all classes.

What We Can Improve Next Time
- Escalate communication issues earlier if a group member becomes unresponsive.
- Set clearer expectations and checkpoints at the start of the project.
- Document our workflow more thoroughly as we go, to avoid last‑minute confusion.
- Allocate buffer time in case unexpected team changes occur
